# 開発規約

WatchFit の構成・命名・テスト・品質チェックの規約。仕様は [要件定義.md](要件定義.md) を正本とする。

## 1. 構成

Vite + React 19 + TypeScript（strict）の単一パッケージ。サーバー側のコードは持たない。

```
.
├── .github/workflows/   # ci.yml（PR・push 検証）、deploy.yml（GitHub Pages）
├── public/              # favicon・アイコン等の静的アセット
├── src/
│   ├── app/             # App.tsx などのアプリの組み立て
│   ├── components/
│   │   ├── editor/      # 画像選択・プレビュー・編集パネル
│   │   ├── watch/       # Watch モデル選択・フレーム表示
│   │   ├── export/      # 保存設定・保存ガイド
│   │   └── ui/          # shadcn/ui のコンポーネント
│   ├── features/        # React に依存しないロジック
│   │   ├── image/       # 検証・デコード・リソース管理
│   │   ├── editor/      # reducer・geometry・constraints・gestures・renderer
│   │   ├── export/      # 画像生成・ダウンロード・共有
│   │   └── watch/       # モデル定義とスキーマ
│   ├── hooks/           # React フック
│   ├── lib/             # 汎用ユーティリティ（shadcn/ui の cn 等）
│   ├── main.tsx
│   └── index.css
└── tests/
    ├── unit/            # src/ の構造を mirror した Vitest テスト
    ├── e2e/             # Playwright テスト
    └── fixtures/        # テスト用画像
```

### 依存方向

- `features/` は React・DOM コンポーネントに依存しない（Canvas・File 等のブラウザ API は使ってよい）
- `components/` と `hooks/` は `features/` を呼ぶ。逆方向の import は禁止
- `index.ts` によるバレルエクスポートは使わない

## 2. 命名

- React コンポーネント: PascalCase（`WatchPreview.tsx`）
- React フック: `useXxx.ts`（`usePointerGestures.ts`）
- それ以外の TypeScript: kebab-case（`decode.ts`, `watch-models.ts`）
- import は `@/` エイリアス（`src/` を指す）を使う

## 3. 実装ルール

- 計算は純粋関数で書き、入力の NaN・Infinity・0 除算を防ぐ
- 編集状態の正本は Output 座標系（要件定義 7.1）
- Reducer に Blob・Canvas・ImageBitmap を入れない（要件定義 11.2）
- エラーメッセージは日本語。スタックトレースを画面に出さない
- 画像内容・元のファイル名をログ（`console` 含む）に出力しない
- 高さ指定は `h-screen` ではなく `h-dvh` / `min-h-dvh` を使う（iOS Safari のアドレスバー対策）
- `'use client'` などの Next.js 固有の記述は使わない

## 4. テスト

| 種類 | ツール | 場所 | 対象 |
|---|---|---|---|
| 単体 | Vitest | `tests/unit/` | `features/` のロジック、Reducer |
| UI | Vitest + React Testing Library | `tests/unit/` | コンポーネントの表示と操作 |
| 描画 | Vitest ブラウザモード（Chromium） | `tests/browser/` | Canvas 描画のピクセル比較（`pnpm test:browser`） |
| E2E | Playwright（Chromium・WebKit の iPhone / デスクトップ） | `tests/e2e/` | 主要フロー、通信監視。Safari 専用の確認は `safari.spec.ts` |

- 要件定義 18章の必須項目・境界値を網羅する
- 外部通信が必要なテストは書かない

## 5. 品質チェック

- `pnpm verify`: Biome lint → `tsc` typecheck → 単体テスト
- CI（`.github/workflows/ci.yml`）は `pnpm verify`・`pnpm build`・描画テスト・E2E を実行し、集約 job `CI ステータス確認`（job ID `ci-status`）で合否を判定する

## 6. ブランチと PR

- 統合ブランチは `main`。直接 push せず、作業ブランチから PR を作成する
- コミットは Conventional Commits（プレフィックスは英語、説明は日本語）
