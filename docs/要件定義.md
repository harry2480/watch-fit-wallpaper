# 0. 文書の位置づけ

本書はWatchFitの要件定義、技術選定、アーキテクチャ、
UI/UX、画像編集アルゴリズム、テスト、デプロイ、
受け入れ基準を統合した実装仕様書である。

開発者およびAIコーディングエージェントは、
本書を実装の基準として使用する。

## 0.1 優先順位

仕様に矛盾がある場合、以下の順で判断する。

1. ユーザー画像のプライバシー保護
2. 画像編集・エクスポートの正確性
3. Apple Watch写真文字盤での実用性
4. iPhoneでの操作性
5. パフォーマンス
6. UIの装飾・追加機能

## 0.2 用語

- Source：読み込んだ元画像
- Output：エクスポートする画像
- Viewport：ブラウザ上の編集プレビュー
- Cover：出力領域を画像で完全に覆う表示方式
- Contain：画像全体が収まる倍率を基準とする表示方式
- Transform：画像の位置・倍率・回転情報
- Preset：Apple Watchモデル別の出力設定
- Safe Area：重要な被写体を配置する推奨領域

## 0.3 実装上の原則

- 本書でMVP必須とした機能は省略しない。
- 未検証のApple Watch仕様を推測で実装しない。
- ユーザー画像を外部サーバーへ送信しない。
- ブラウザ内で完結しない画像処理を導入しない。
- プレビューと出力に共通の画像変換ロジックを使用する。
- 不要なライブラリや抽象化を追加しない。
- 未実装機能を動作するように見せかけない。
- 外部サービスを導入する場合は要件変更を必要とする。

# 1. プロジェクト概要

## 1.1 背景

Apple Watchの写真文字盤に画像を設定すると、
以下の問題が発生することがある。

- 画像の縦横比が画面と一致しない。
- 人物やキャラクターの顔が切れる。
- 被写体が意図しない位置に配置される。
- 画像が拡大されすぎる。
- 画像全体を表示したいのにトリミングされる。
- 時計表示が被写体に重なる。
- Apple Watch上での表示を事前に想像しにくい。

一般的な画像トリミングツールでは、
Apple Watchのモデル別画面比率や表示領域を
考慮した調整が難しい。

## 1.2 目的

ユーザーが任意の画像を読み込み、
Apple Watchの画面を模したプレビュー上で
画像の位置・大きさを自由に調整し、
適切な解像度で保存できるWebアプリを提供する。

## 1.3 コンセプト

「好きな写真を、好きな位置で、Apple Watchに。」

基本操作は以下の3ステップとする。

1. 画像を選択
2. 位置・大きさを調整
3. 画像を保存

## 1.4 成功条件

以下を満たすこと。

- iPhoneだけで一連の操作を完了できる。
- 画像の位置と倍率を自由に調整できる。
- CoverとContainの両方に対応する。
- プレビューと保存画像の構図が一致する。
- Apple Watchのモデル別解像度で保存できる。
- ユーザー画像を外部送信しない。
- GitHub Pagesのみで運用できる。
- ログイン・課金・インストールを必要としない。

## 1.5 制約

Apple Watchの写真文字盤はwatchOS側で
画像の表示位置や拡大率を再調整する可能性がある。

本アプリは画像ファイルの生成までを制御する。

Apple Watch側の表示処理を直接変更したり、
完全に固定したりすることはできない。

したがって、以下を区別する。

A. アプリ内プレビューと出力画像の一致
   → 必須保証対象

B. Apple Watch実機での表示一致
   → 実機検証対象。完全一致は保証しない。

# 4. Apple Watchモデル仕様

## 4.1 モデル選択

ユーザーは以下を選択する。

1. Apple Watchシリーズ
2. ケースサイズ

モデル選択後、対応する画面解像度を
エクスポート設定に適用する。

## 4.2 対応対象

初期対象：

- Apple Watch Series 7以降
- Apple Watch SEシリーズ
- Apple Watch Ultraシリーズ
- カスタム解像度

発売済みモデルのみ登録する。

## 4.3 解像度の管理

Apple公式の製品仕様・技術資料を
優先して解像度を確認する。

公式資料で確認できない場合は、
信頼できる複数の情報源で照合する。

未検証の解像度を推測で登録しない。

モデル追加時は、確認元と確認日を記録する。

## 4.4 データ構造

type WatchModel = {
  id: string;
  series: string;
  label: string;
  caseSizeMm: number;
  widthPx: number;
  heightPx: number;
  cornerRadiusRatio: number;
  verified: boolean;
  sourceUrl?: string;
  verifiedAt?: string;
};

## 4.5 カスタム解像度

ユーザーが幅と高さを指定できる。

入力制約：

- 幅：100〜2048px
- 高さ：100〜2048px
- 整数のみ
- 0・負数・NaNを禁止
- 不正値では出力不可

カスタム解像度では
汎用の角丸長方形プレビューを使用する。

## 4.6 モデル変更時の挙動

モデル変更時は、画像中心の相対位置と
見た目の相対サイズを維持する。

旧出力サイズをW1、H1、
新出力サイズをW2、H2とする。

画像中心は次のように変換する。

newCenterX = oldCenterX * W2 / W1
newCenterY = oldCenterY * H2 / H1

倍率は以下の比率で補正する。

newScale = oldScale * min(W2 / W1, H2 / H1)

補正後、Coverモードの場合は
画面全体を覆う最小倍率と位置制約を再適用する。

異なる縦横比のモデル間では、
構図の完全維持は保証しない。

# 5. 画像入力仕様

## 5.1 対応形式

必須：
- JPEG
- PNG
- WebP

条件付き：
- HEIC
- HEIF

HEIC / HEIFはブラウザがデコードできる場合のみ
MVPで対応する。

未対応環境では変換案内を表示する。

非対応：
- SVG
- GIFアニメーション
- 動画
- PDF
- RAW画像

## 5.2 ファイル選択

以下に対応する。

- ファイル選択ダイアログ
- iPhoneの写真ライブラリ
- PCでのドラッグ＆ドロップ

MVPでは同時に1画像のみ編集する。

新しい画像を選択した場合、
現在の編集内容が失われることを
必要に応じて案内する。

## 5.3 入力制限

- ファイルサイズ上限：30MiB
- デコード後の上限：50メガピクセル
- 同時編集画像：1枚

ファイルサイズだけでなく、
画像のデコード後サイズを検証する。

巨大画像を無制限にCanvasへ展開しない。

## 5.4 ファイル検証

以下を確認する。

1. ファイルが存在すること
2. ファイルサイズが制限内であること
3. 対応形式であること
4. 実際に画像としてデコードできること
5. 幅・高さが有効であること
6. ピクセル数が上限内であること

拡張子やMIME typeだけを信用しない。

## 5.5 EXIF Orientation

画像の向きが正しくなるようにする。

ブラウザのデコーダーによる自動回転と
独自のOrientation補正を二重適用しない。

画像デコード後の実寸法を正本として扱う。

対応ブラウザで異なる挙動が発生しないか、
Orientation 1〜8のテスト画像で検証する。

## 5.6 色空間

sRGBを基本とする。

Canvasが対応する環境では
sRGBの明示的な指定を検討する。

Display P3などの画像では、
ブラウザによって色が変化する可能性がある。

MVPでは高度なICCプロファイル変換は実装しない。

## 5.7 リソース管理

画像デコード後はImageBitmapを優先使用する。

非対応環境ではHTMLImageElementを使用する。

画像変更時・コンポーネント破棄時には
不要なリソースを解放する。

- ImageBitmap.close()
- URL.revokeObjectURL()
- Canvas参照の解放

古い画像の非同期デコード完了によって、
新しい画像が上書きされないようにする。

# 6. 画像編集モード

## 6.1 共通仕様

編集モードは以下の2種類。

- Cover
- Contain

両モードは同じ描画エンジンを使用する。

違いは以下とする。

- 初期倍率
- 最小倍率
- 位置制約
- 余白の許容

## 6.2 Coverモード

目的：
出力領域を画像で完全に覆う。

仕様：

- 初期倍率はCover倍率
- 余白を許可しない
- ドラッグで位置変更可能
- ピンチズーム可能
- スライダーでズーム可能
- 最小倍率はCover倍率
- 最大倍率はCover倍率の4倍
- 画像が領域外へ移動しすぎないよう制約する

## 6.3 Containモード

目的：
画像全体を表示できる状態から編集を開始する。

仕様：

- 初期倍率はContain倍率
- 余白を許可する
- ドラッグで自由に位置変更可能
- 拡大縮小可能
- 画像が部分的に切れてもよい
- 背景色を設定可能

倍率範囲：

- 最小：Contain倍率の0.25倍
- 最大：Contain倍率の4倍

この倍率範囲はUIの初期仕様とし、
実機で操作性を確認して調整可能とする。

## 6.4 モード切り替え

Cover → Contain：

- 現在の画像位置と倍率を原則維持
- 余白を許可する
- 現在倍率がContainの許容範囲外の場合は補正

Contain → Cover：

- 現在の構図をできる限り維持
- Cover最小倍率を下回る場合は拡大
- 位置制約を再適用
- 余白をなくす

モード切り替えによって
無条件に画像を中央へ戻してはならない。

## 6.5 フィット操作

「フィット」ボタンは、
現在モードの基準倍率に設定する。

Cover：
Cover倍率で中央配置。

Contain：
Contain倍率で中央配置。

## 6.6 リセット操作

リセット時は以下を初期化する。

- 画像位置
- 画像倍率
- 画像回転

背景色とWatchモデルは維持する。

モードは現在の選択を維持する。

# 7. 画像編集エンジン

## 7.1 座標系

3種類の座標系を使用する。

Source：
元画像のピクセル座標。

Output：
出力画像のピクセル座標。

Viewport：
ブラウザ上のプレビュー座標。

編集状態はOutput座標系で管理する。

ViewportのCSSサイズに依存する値を
編集状態の正本にしない。

## 7.2 基準倍率

元画像：

Iw = 画像幅
Ih = 画像高さ

出力画像：

W = 出力幅
H = 出力高さ

Cover倍率：

coverScale = max(W / Iw, H / Ih)

Contain倍率：

containScale = min(W / Iw, H / Ih)

## 7.3 Transform

type ImageTransform = {
  centerX: number;
  centerY: number;
  scale: number;
  rotationDeg: number;
};

centerX / centerY：
Output座標上の画像中心。

scale：
Source座標からOutput座標への絶対倍率。

rotationDeg：
画像の回転角度。

MVPではrotationDegを0に固定する。

## 7.4 初期配置

画像を読み込んだ際は、
現在のモードに応じた倍率で中央配置する。

centerX = W / 2
centerY = H / 2

Cover：
scale = coverScale

Contain：
scale = containScale

## 7.5 Cover位置制約

回転0度の場合、

Dw = Iw * scale
Dh = Ih * scale

画像中心の許容範囲：

W - Dw / 2 <= centerX <= Dw / 2
H - Dh / 2 <= centerY <= Dh / 2

ドラッグ・ズーム・モデル変更後に
この制約を適用する。

浮動小数点誤差によって
画面端に1px程度の余白が発生しないよう、
描画と制約の境界条件をテストする。

## 7.6 Contain位置制約

Containでは画像の部分的な画面外移動を許可する。

ただし、完全に操作不能になることを防ぐため、
最低16 Output px相当の画像領域が
出力範囲内に残るよう制約する。

この値は出力サイズに対して過大にならないよう、
画像・出力サイズに応じて調整する。

## 7.7 ドラッグ

Pointer Eventsを使用する。

pointerdown：
操作開始座標を記録。

pointermove：
移動量をOutput座標へ変換。

pointerup：
操作を終了。

pointercancel：
操作状態を安全に解除。

pointer captureを使用し、
ドラッグ中に指が要素外へ移動しても
操作が不自然に中断されないようにする。

## 7.8 Viewport座標変換

Viewport上の画像描画領域を

Vw × Vh

とする。

Outputが

W × H

の場合、移動量は以下。

deltaOutputX = deltaViewportX * W / Vw
deltaOutputY = deltaViewportY * H / Vh

ただし、CSSによる余白やオフセットを含む
実際の描画矩形を基準に変換する。

ブラウザのdevicePixelRatioと
CSSピクセルを混同しない。

## 7.9 ピンチズーム

2本指のPointer Eventsを追跡する。

開始時に以下を保存する。

- 2点間の距離
- 2点の中心座標
- 現在倍率
- 現在の画像中心

ズーム倍率：

newScale =
startScale * currentDistance / startDistance

倍率はモード別の範囲に制限する。

ズーム中心にある元画像上の点が、
操作前後で同じ画面位置に残るよう
画像中心を補正する。

ピンチ中心が移動した場合は、
2本指によるパン操作も反映する。

## 7.10 ホイールズーム

マウスカーソル位置をズーム中心とする。

wheel.deltaModeを考慮して入力を正規化する。

倍率変更は指数関数的な変化を基本とし、
急激な拡大縮小を防ぐ。

編集領域上でズームを扱う場合のみ、
必要な範囲でブラウザ標準スクロールを抑制する。

## 7.11 スライダー

ズームスライダーは相対倍率を表示する。

100%は現在モードの基準倍率を意味する。

ただし、モード切り替え後の実倍率は維持するため、
スライダー表示値が100%とは限らない。

倍率の変更には共通のズーム処理を使用する。

## 7.12 描画更新

Pointer Eventsの発生ごとに
Reactツリー全体を再描画しない。

requestAnimationFrameを使用し、
1フレームにつき最大1回のCanvas描画にまとめる。

編集状態の確定値はReducerで管理する。

ドラッグ中の高頻度な中間値は
必要に応じてRefに保持する。

操作終了時に状態を確定する。

# 8. Canvas描画仕様

## 8.1 描画順序

1. Canvasサイズを設定
2. 変換行列を初期化
3. 背景を描画
4. 画像中心へ座標移動
5. 回転を適用
6. 倍率を適用
7. 元画像を描画
8. 描画状態を復元

## 8.2 共通レンダラー

type RenderParams = {
  source: CanvasImageSource;
  sourceWidth: number;
  sourceHeight: number;
  outputWidth: number;
  outputHeight: number;
  transform: ImageTransform;
  backgroundColor: string;
};

renderImage(
  ctx: CanvasRenderingContext2D,
  params: RenderParams
): void

プレビューと出力は
この共通レンダラーを使用する。

## 8.3 プレビュー

プレビューは論理的にOutput座標で描画する。

CSSによってApple Watch画面サイズへ縮小表示する。

プレビューの描画解像度は、
出力サイズ・CSS表示サイズ・devicePixelRatioを考慮し、
過剰なCanvasメモリ消費を避ける。

高DPI対応による追加スケーリングは
描画行列で一元管理する。

## 8.4 Apple Watchフレーム

Apple Watchの外観は
画像描画Canvasと分離する。

フレームはCSSまたはSVGで表示する。

表示要素：

- ケース外形
- ディスプレイ枠
- 角丸マスク
- 必要な場合の簡易ベゼル

モデル別の外観を完全再現することは
MVPの必須要件ではない。

画面の縦横比と編集範囲の正確性を優先する。

## 8.5 角丸

プレビューには角丸マスクを適用する。

ただし、エクスポート画像には適用しない。

出力は通常の長方形画像とする。

角丸領域を透明にしてはならない。

## 8.6 背景

MVPは単色背景を使用する。

初期値：

#000000

ユーザーはカラーピッカーで変更できる。

PNG出力でも背景は不透明とする。

Phase 2では背景ぼかしを追加する。

# 9. エクスポート

## 9.1 出力形式

- PNG
- JPEG

初期値はPNG。

JPEG品質の初期値は0.92。

JPEG品質は0.5〜1.0の範囲で指定できる。

## 9.2 出力解像度

選択したWatchモデルの
widthPx × heightPxを使用する。

カスタム解像度の場合は
ユーザーが指定した値を使用する。

CSS上のプレビューサイズを
出力解像度に使用してはならない。

## 9.3 描画内容

含める：

- 背景
- 編集済み画像

含めない：

- Apple Watchケース
- ベゼル
- 時計表示
- ガイド線
- 選択枠
- 編集UI

## 9.4 画像生成

出力用Canvasを別途生成する。

現在の編集状態をスナップショットとして取得し、
その値から画像を生成する。

toBlob()を基本とする。

Blob生成失敗時はエラーを表示する。

出力完了後は不要なCanvasを解放する。

## 9.5 メタデータ

元画像のEXIF情報を引き継がない。

特に以下を出力しない。

- GPS位置情報
- 撮影機器情報
- 撮影日時
- 元画像のファイル名

Canvasから生成した画像に
不要な元画像メタデータが含まれないことを
テストする。

## 9.6 ファイル名

形式：

watchfit-{modelId}-{timestamp}.{ext}

例：

watchfit-series11-46mm-20261117-203000.png

timestampはローカル日時を使用する。

ファイル名に元画像名を含めない。

## 9.7 iPhone保存

対応環境ではWeb Share APIを使用する。

navigator.canShare({ files })で
ファイル共有の可否を確認する。

共有可能な場合：

navigator.share({ files })

共有不可の場合：

Blob URLによるダウンロードを試みる。

ブラウザの制限によって保存できない場合は、
画像を表示して手動保存する導線を提供する。

ユーザーによる共有キャンセルは
エラーとして扱わない。

Web Share APIはユーザー操作に伴う
一時的な権限が必要なため、
画像生成と共有呼び出しのタイミングに注意する。

非同期処理後に共有権限が失われる環境では、
生成済み画像を明示的な保存ボタンから共有する。

## 9.8 PC保存

Blob URLとdownload属性を使用する。

保存後はObject URLを解放する。

## 9.9 保存完了後

以下の案内を表示可能にする。

1. iPhoneの写真アプリに画像を保存
2. Watchアプリを開く
3. 写真文字盤を選択
4. 保存した画像を指定
5. Apple Watchに文字盤を追加

watchOSのバージョンによって操作が異なるため、
案内は公式手順に合わせて更新する。

## 12.4 復旧

エラーによって画面全体が
操作不能にならないようにする。

新しい画像を選び直せる状態を維持する。

# 13. パフォーマンス要件

## 13.1 目標

- LCP：2.5秒以内を目標
- ドラッグ：60fpsを目標
- ズーム：60fpsを目標
- 通常画像の出力：3秒以内を目標

性能目標は計測環境を固定して評価する。

## 13.2 最適化方針

- 不要なReact再レンダリングを避ける
- requestAnimationFrameで描画を制御
- ImageBitmapを優先利用
- 不要なCanvasを解放
- 高解像度画像の過剰なデコードを避ける
- 重い画像処理ライブラリを導入しない
- コード分割を必要に応じて使用

## 13.3 メモリ管理

画像ファイルサイズと
デコード後のメモリ使用量は異なる。

RGBA画像は概算で

width * height * 4 bytes

のメモリを必要とする。

元画像・プレビュー・出力Canvasが
同時に存在することを考慮する。

画像のデコードやCanvas確保に失敗した場合は、
安全に処理を中止する。

## 13.4 低性能端末

高解像度画像で操作が重い場合は、
編集用の縮小画像を使用できる構造とする。

縮小画像を使用する場合も、
座標系と出力結果の整合性を維持する。

最終出力に使用する画像の品質を
不必要に低下させない。

# 14. プライバシー・セキュリティ

## 14.1 最重要要件

ユーザー画像を外部サーバーに送信しない。

画像はユーザーのブラウザ内でのみ処理する。

## 14.2 禁止事項

- 画像の外部アップロード
- 外部画像変換API
- 画像を含むログ送信
- 外部解析サービスへの画像情報送信
- ユーザー画像の自動クラウド保存
- 画像を含むURLの生成
- 画像データをクエリパラメータに含めること

## 14.3 ログ

画像内容をログに出力しない。

元画像のファイル名も
原則としてログへ出力しない。

## 14.4 サードパーティ

実行時に外部CDNや
外部画像処理サービスを使用しない。

フォント・アイコンなども
原則としてローカルにバンドルする。

## 14.5 CSP

GitHub Pagesではレスポンスヘッダーの
自由な設定に制限がある。

CSPを設定する場合は、
metaタグで実現可能な範囲を使用する。

必要なBlob URL等を許可しつつ、
不要な外部通信を制限する。

CSPだけを画像非送信の保証手段としない。

## 14.6 検証

ブラウザのNetworkパネルと
自動テストで通信先を確認する。

画像編集・保存操作中に
画像データを含む外部リクエストが
発生しないことを確認する。

# 22. 品質上の禁止事項

以下の実装は禁止する。

- プレビューと出力で異なる座標計算を使用する
- CSSの見た目だけで画像を調整する
- 出力時に別のトリミング計算を行う
- Coverモードで余白を許可する
- 画像の縦横比を勝手に変更する
- 画像をサーバーへ送信する
- 不要な外部画像処理ライブラリを導入する
- Canvasを解放せず保持し続ける
- 不正なモデル解像度を推測で登録する
- Apple Watch実機での完全一致を保証すると表記する
- iPhoneで保存できない方式だけを提供する
- テストを省略して完了扱いにする

# 26. 完了の定義

WatchFitのMVPは、
ユーザーがiPhoneからGitHub Pages上のサイトへアクセスし、
任意の画像を選択して、
Apple Watchの画面に合わせて位置と大きさを調整し、
PNGまたはJPEGで保存できる状態をもって完成とする。

この一連の処理で、
画像データが外部サーバーに送信されてはならない。

プレビューと出力画像の構図は一致しなければならない。

Apple Watch実機での表示については、
検証結果と既知の制限事項を明示する。
